# Исходники и сборка

Готовое приложение — корневой `onehtml-lab.html`: самостоятельный HTML-файл без зависимостей во время работы. Этот файл создаётся из исходников и не включается в коммиты. Actions собирает его перед тестами и при публикации выпуска; готовый файл прикрепляется к выпуску. Для GitHub Pages из той же сборки создаётся копия с именем `index.html`. Коммиты в `main` запускают проверки, но не обновляют Pages; страница обновляется при публикации выпуска.

Для пересборки и проверок нужен Node.js 20 или новее. Из корня проекта выполните:

```cmd
node build.mjs
```

`src/template.html` задаёт разметку и политику безопасности, `src/styles.css` — оформление, `src/icons/` — SVG-значки, а `src/examples/` — игры-примеры. `src/app.js` управляет интерфейсом, `src/draft.js` хранит черновик и историю в IndexedDB, `src/compare.js` строит различия, `src/exporter.js` сохраняет и отправляет файл, `src/library-bundle.js` распознаёт точные версии классических библиотек по адресам CDN и локальным путям, загружает их вместе с MIT-лицензией по явному действию пользователя и хранит в отдельной базе IndexedDB, а `src/sandbox.js` создаёт изолированный предпросмотр и сообщает об ошибках игры. Локальный JS с лицензией также можно выбрать вручную; такая копия привязывается к SHA-256 исходного HTML и пути подключения, чтобы одинаковые имена файлов в разных играх не выбирали чужой код. При недоступном Web Crypto выбор действует только в сеансе. Все поддерживаемые библиотеки, включая Three.js r128, доступны для загрузки; готовых копий библиотек игр в сборке редактора нет. Подготовленное встраивается в сохранённую игру с выбранным флажком «Встроить библиотеки в файл». Для запуска самого редактора внешние шрифты, библиотеки и сервер не используются.

Экспорт с библиотеками поддерживает один HTML со встроенным кодом или отдельное скачивание HTML и JS-файлов. `src/exporter.js` подготавливает относительные ссылки и передаёт каждый файл браузеру через Blob без сетевых запросов. Имена версий и разрешение совпадений позволяют хранить все файлы в одном каталоге, MIT-лицензии включаются в JS. После передачи файлов окно сохранения показывает кнопки для скачивания каждого по отдельности, если браузер ограничил множественное скачивание. Проверки подготовки файлов входят в `test:unit`; браузерные проверки `test:libraries` скачивают HTML и JS, проверяют повторное скачивание при блокировке и запускают комплект из локального каталога.

`src/library-extract.js` выполняет обратное преобразование встроенных копий OneHTML Lab в CDN-ссылки той же версии или относительные подключения. Новое встраивание записывает исходный адрес, имя, доступный CDN-адрес и SHA-256 кода, а лицензия находится в отдельном помеченном комментарии. Вынос проверяет эти сведения без выполнения JS, переносит код вместе с лицензией в кэш с ключом по SHA-256 их содержимого и сохраняет полный HTML в истории. Старые помеченные копии требуют точного совпадения с кэшем; непомеченные или изменённые блоки не удаляются. Для контрольных сумм LF и CRLF приводятся к одному виду. Маленькие подключения сохраняют метку кэшированной копии, поэтому последующие правки игры не теряют её и не подменяют глобальный каталог версий. Окно сохранения выбирает подходящий вариант по этим подключениям. Логика входит в `test:unit` и чистую проверку; `test:libraries` дополнительно проверяет интерфейс, историю, кэш после перезагрузки и запуск отдельных файлов в Chromium и WebKit.

`src/workspace.js` управляет экранами рабочей области, возвратом к позиции кода, разворотом игры и общей строкой сообщений. Вспомогательные экраны сохраняют существующий iframe; открытие и закрытие меню не создаёт игру заново. Проверка `npm run test:workspace` охватывает переходы, выделение и прокрутку, сохранение при уменьшенной высоте, сообщения и разворот на мобильных и настольных размерах в Chromium и WebKit.

`src/editor.js` добавляет поиск, замену, навигацию и настройки нативного текстового поля. Отмена хранит текстовые изменения, до 100 действий с бюджетом 8 миллионов кодовых единиц; последнее действие сохраняется даже при превышении бюджета. Настройки вида находятся в отдельном ключе localStorage. Номера строк рисуются только для видимой области, геометрия переносов измеряется без исполнения HTML. В невидимой измерительной копии строки разделены на блоки, чтобы браузер не рассчитывал большой документ как один абзац с переносами. Переход к ошибке учитывает служебный префикс предпросмотра и доступен только при точном соответствии исходнику. Проверка `npm run test:editor` охватывает Chromium и WebKit, мобильные и настольные размеры, отмену, буквальные замены, сохранение настроек и документ размером более 2 МБ.

Поиск размещён над нативным полем кода, а кнопки точечной правки — под ним; их измеренная высота вычитается из области текста, включая режим разделённого экрана. Подсветка найденного фрагмента строится по безопасной измерительной копии и не меняет исходник. Отступы и парные символы используют общую цепочку отмены. `tests/editor-touch.mjs` входит в `test:editor` и проверяет сенсорные действия, границы выделения, копирование с отказом буфера, режим только чтения, подсветку без фокуса в коде и уменьшенную высоту окна. Уменьшение окна моделирует доступное место; физическая экранная клавиатура браузерным тестом не проверяется.

`src/ai-prompts.js` готовит запросы для игры или мультимедийного приложения, показывает текст и число символов перед копированием. Тип работы задаётся явно; открытие известного примера выбирает соответствующий тип, произвольная вставка/импорт/возврат его не меняют. Ключ localStorage `onehtml-lab-ai-settings` хранит тип, устройство, задачу, пожелания по пяти задачам и флажки запроса; повреждённые значения игнорируются, отказ хранения оставляет настройки в сеансе. Необязательные заготовки дописывают задачу, не заменяя пожелания и исходник. Сокращение вызывает только читающую часть `planLibraryExtraction`: проверяет библиотеку и MIT-лицензию, заменяет её точной CDN-ссылкой в копии, не меняет редактор, историю или кэш и не делает сетевых запросов. Результат асинхронной проверки применяется только к актуальным параметрам запроса. Проверка `npm run test:ai` охватывает Chromium и WebKit, локальный файл и HTTP, размеры экрана, сообщения об ошибках, отказ буфера, сохранность исходника и библиотек, а также смену задачи во время проверки.

`src/ai-session.js` хранит до 20 точных скопированных запросов в IndexedDB `onehtml-lab-ai/prompts`. Добавление и удаление старых записей атомарны; отказ оставляет историю в памяти. Исходник связан SHA-256 и областью работы без второй полной копии HTML. Повторное копирование восстанавливает прежние привязки медиа; повторное использование пожеланий готовит новый запрос с текущим кодом. Приём ответа разбирает Markdown как текст, не исполняя HTML; выбор блока и сравнение предшествуют явной замене. Сравнение закреплено за исходником, областью и ответом, устаревшее нельзя применить. `npm run test:ai-session` проверяет оба редактора через file/HTTP, перезапуск, буфер, историю и приём ответа. Unit-проверка входит в чистую копию и общий набор. Бюджет сборки — 1 350 000 байт, без добавления игровых библиотек в комплект.

`tests/ai-applications-unit.mjs` проверяет шаблоны создания, изменения, исправления и анализа для обоих основных устройств и входит в unit и чистую копию. Сквозной `tests/ai-applications.mjs` входит в `test:ai`; отдельно доступен `npm run test:ai-applications`. Он проверяет необязательные заготовки, сохранение выбора, свои изображение/звук, копирование запроса, вставку подготовленного ответа, запуск без сети, историю, обратный импорт и автономное сохранение. Используются оба редактора, file/HTTP и ширины 320/1365; отдельно проверяются уменьшенная высота, альбомный экран и недоступное/повреждённое хранилище. Ответ бота задан тестом: внешнему ИИ код и файлы не отправляются, качество генерации им не оценивается.

`src/desktop.js` управляет расположением кода и игры рядом на экранах от 1000 пикселей, разделителем и размером предпросмотра. Настройки хранятся в отдельном ключе localStorage. Изменение расположения и масштаба сохраняет тот же iframe; ручной перезапуск создаёт новый. Размер телефона задаётся до подключения iframe к документу. Ошибки привязаны к запущенному исходнику, чтобы правки редактора не приводили к переходу на неверную строку или подготовке запроса по другой версии. Проверка `npm run test:desktop` охватывает Chromium и WebKit: изменение размеров, сохранность игры, редактирование, перезапуск, экспорт и настройки. Вариант `node tests/desktop.mjs --http` дополнительно проверяет HTTP через временный локальный сервер.

`src/diagnostics.js` расширяет экран сообщений списком последних 50 различных событий запуска и управлением библиотеками. Повторы объединяются; исходник и доступные позиции ошибки привязаны к конкретному запуску. Проба в изолированном iframe сообщает об ошибках, отклонениях Promise, `console.warn`, `console.error` и ошибках ресурсов, сохраняя штатный вызов консоли. Поток ограничен 100 сообщениями в секунду с отдельным предупреждением; интерфейс обновляет список не чаще десяти раз в секунду при поступлении сообщений. Отчёт не включает HTML; подготовка ИИ-запроса может добавить его через существующий механизм.

Список библиотек разбирает текущий текст без исполнения и сетевых запросов, использует существующие правила распознавания и загрузки с MIT-лицензиями. Постоянные и временные копии различаются по фактически сохранённой записи. Удаление выполняется одной транзакцией только в базе библиотек; память меняется после успешного завершения. При отказе транзакции список сохраняется. Проверка `npm run test:diagnostics` охватывает Chromium и WebKit, узкий и широкий экран, ошибки и повторы, безопасный вывод текста, отчёт и связь с исходником, встроенные и внешние подключения, локальные файлы, отказ удаления, перезагрузку и недоступную IndexedDB. Вариант `node tests/diagnostics.mjs --http` дополнительно проверяет HTTP.

`src/readiness.js` добавляет разделы ресурсов и скорости. Статический текстовый разбор HTML и встроенных стилей не подключает пользовательский DOM и не выполняет запросов. В списке запуска объединяются Resource Timing, ошибки ресурсов и события CSP; принимаются только сообщения действующего iframe, число адресов ограничено 200. Измерение интервалов `requestAnimationFrame` выключено по умолчанию, при включении сообщает результат раз в секунду и исключает фоновые и вспомогательные экраны. Пробы добавляются только в предпросмотр, экспорт игры их не содержит. Проверка `npm run test:readiness` охватывает Chromium и WebKit, мобильный и настольный размеры, статические и динамические ресурсы, блокировку сети, подстановку библиотеки, FPS, отчёт, смену исходника и сохранение настройки. Вариант `node tests/readiness.mjs --http` добавляет HTTP; разбор ресурсов и часы измерения также проверяются в `test:unit`.

Проверка `npm run test:workshop` проходит сценарий занятия в Chromium и WebKit: памятку, готовую игру без сети, замену текста, ошибочный и исправленный ответы ИИ, сравнение, возврат версии, скачивание и запуск отдельного HTML. Ответы ИИ и доступ к буферу подставляются тестом; реальные сервисы и системное меню вставки не вызываются. Сетевые запросы блокируются; для Chromium дополнительно включён режим offline, а WebKit проверяется блокировкой запросов из-за ограничения навигации по локальным файлам в его режиме offline. Проверки выполняются на узком и широком экране, без физических телефонов.

`src/syntax.js` содержит собственный ограниченный разбор HTML/CSS/JavaScript для оформления. Цветной слой строится только для видимых строк через текстовые узлы; нативное поле сохраняет ввод, выделение и прокрутку. Подключения получают пояснения, CSS-цвета — образцы с контрастными буквами и шахматной подложкой для прозрачности. Цвет букв выбирается по контрасту с обеими клетками после наложения альфа-канала. Оформление образца не меняет размеры символов. Это подсветка, а не полный анализатор языка или проверка ошибок. При вводе через IME временно виден обычный текст. Файлы больше миллиона кодовых единиц UTF-16, строки длиннее 12 тысяч и результаты больше 60 тысяч токенов показываются без подсветки. Разбор входит в `test:unit`; `test:syntax` проверяет Chromium и WebKit, геометрию текста, настройки, ввод, поиск, отсутствие исполнения исходника и точное сохранение HTML.

`src/comparison-game.js` запускает текущий исходник и выбранную запись истории в отдельном sandbox iframe. Одновременно существует только один iframe сравнения; смена версии, вкладка кода и закрытие удаляют его. Сеанс содержит два ограниченных временных хранилища, не зарегистрированных в постоянном хранилище игры. Сообщения принимаются только от действующего iframe, асинхронная подготовка отменяется счётчиком запуска. Загрузка и выбор библиотек используют общий механизм с привязкой к сеансу и версии вместо текста редактора. `test:comparison-game` проверяет выбор записи, изоляцию, временные данные, ошибки, сеть, CDN и локальные библиотеки, неизменность экспорта и отмену запуска в Chromium/WebKit на узком и широком экранах.

`src/alternative-editor.js` подключает CodeMirror 6 к общему исходнику и цепочке отмены обычного редактора. CodeMirror используется по умолчанию; разбор HTML со встроенными CSS/JavaScript поддерживает ручное сворачивание и общие смысловые акценты. Видимые блоки не определяют экспорт: все действия используют полный текст. Переключатели редактора и темы закреплены справа в нижней панели в обоих режимах. Выбор хранится в отдельных ключах localStorage; сворачивание действует в сеансе. Тёмная тема задаёт отдельные цвета подсветки и не меняет документ игры. `test:alternative-editor` проверяет Chromium и WebKit на узком и широком экранах: начальные настройки, переключение без потери кода и курсора, закреплённые кнопки, обе темы и их сохранение, сворачивание, копирование скрытого текста, поиск, отмену, вставку и историю, импорт, экспорт, режим только чтения, предпросмотр и работу без сети. Остальные сценарии явно выбирают обычный редактор через `tests/native-editor.mjs`, сохраняя проверку его собственного ввода и геометрии.

Готовая копия CodeMirror находится в `src/vendor/codemirror.bundle.js` и включается обычной сборкой без npm, сети и каталога `local/`. Для её обновления после установки зависимостей выполните `npm run build:editor`, затем `npm run build`. `scripts/build-codemirror.mjs` собирает `src/codemirror-entry.js` через esbuild и автоматически сохраняет полные MIT-лицензии всех вошедших пакетов в JS, `src/vendor/codemirror-LICENSE.txt` и список версий в [THIRD_PARTY.md](THIRD_PARTY.md). Дополнительные разделы THIRD_PARTY начиная с первого заголовка второго уровня сохраняются. Неизвестная лицензия останавливает пересборку. Эти три результата нужно проверять вместе. Встроенный редактор увеличивает HTML примерно на 500 КБ; актуальный бюджет полного приложения задан в `tests/build.mjs`.

«Умное сворачивание» использует смешанное дерево HTML/CSS/JavaScript/JSON уже включённого парсера. Оболочка html/head/body остаётся открытой; стили и скрипты сворачиваются от двух переводов строки или 120 единиц UTF-16 содержимого, прочие HTML-контейнеры — от восьми переводов строки или 600 единиц. Функции, методы и классы сворачиваются независимо от длины, другие блоки, массивы и объекты — от двух переводов строки или 120 единиц. Диапазоны сохраняются на всех вложенных уровнях: раскрытие родителя не раскрывает потомков. Для стрелочных функций с выражением и JSON добавлен также сервис ручного сворачивания. Нажатие заглушки раскрывает именно её диапазон, включая случай нескольких функций в одной строке. Незакрытые или несовпадающие теги и скобки не используются как границы.

Перед применением диапазонов исключаются избыточные вложенные обёртки. Если родитель содержит один дочерний диапазон и вокруг содержащей его синтаксической конструкции только пробелы, комментарии или разделители, дочерний диапазон пропускается. Цепочки проверяются по исходной иерархии; соседний код и несколько дочерних блоков сохраняют отдельное сворачивание. Комментарии и разделители берутся из дерева, а не распознаются внутри строк как код. Ручное сворачивание не фильтруется.

Режим по умолчанию выключен и сохраняется в `onehtml-lab-smart-fold`. Включение, вставка, полная замена и восстановление черновика запрашивают сворачивание только в CodeMirror; обычный ввод его не запускает. Запрос ждёт окончания вставки и закрытия панели. Разбор уступает интерфейсу между порциями; изменение документа, ручное действие в редакторе или отключение режима отменяет устаревшую операцию. «Развернуть всё» отменяет ожидающую операцию и раскрывает все уровни, оставляя режим включённым. Текст и цепочка отмены не меняются. `tests/structure-fold.mjs` входит в тест редактора и проверяет вложенность, одиночные обёртки, обе темы, ручное сворачивание, вставку обоими способами, импорт, возврат версии, сохранение режима, запасной редактор, редактирование, длинные однострочные скрипты и повреждённый HTML; проверки учитывают виртуальную прокрутку редактора.

Черновик и история записываются одной транзакцией IndexedDB с проверкой ревизии. Несовпадение ревизии приостанавливает запись до явного продолжения в этой вкладке; чужая сохранённая версия переносится в историю в той же транзакции. Существующие ключи черновика и миграция предыдущей версии сохранены. События скрытия страницы и ухода со страницы запускают ожидающее сохранение, но завершение записи при принудительном закрытии браузера не гарантируется.

Единый набор проверок для коммитов и выпусков запускается командой `npm run test:check`: сборка, проверки поставки, модульные проверки, чистая копия и браузерные сценарии Chromium. `tests/check.mjs` не публикует файлы и не обращается к API GitHub. Параметр `--release-tag=v1.2.3` собирает и проверяет локальный HTML с заданной меткой версии. Отдельные наборы по-прежнему доступны; `npm run test:reliability` проверяет оба редактора в Chromium/WebKit, файловый и HTTP-запуск, конфликт вкладок, сохранение при скрытии страницы и отказ транзакции.

`tests/run-browser.mjs` запускает браузерный сценарий с диагностикой. При неудаче остаются журнал, снимки последних страниц и трассировки Playwright для последних шести контекстов. Трассировку можно открыть локально командой `npx playwright show-trace` с путём к `trace.zip`. Эти проверки используют тестовые данные; они не подтверждают работу системного буфера, отправки файлов и выгрузки вкладки на физическом телефоне.

## Подготовка модульного ядра

`src/library-modules.js` разбирает статические импорты включённым HTML/JavaScript-парсером CodeMirror без выполнения кода. Каталог ограничен ядром Three.js r160–r180, точными CDN-адресами jsDelivr/unpkg и внутренними файлами `three.module(.min).js` / `three.core(.min).js` того же выпуска. Загрузка с явным подтверждением получает до трёх файлов суммарно до 4 МиБ и MIT-лицензию до 64 КиБ; неполный граф или отсутствующая лицензия не попадают в кэш. Нет дополнительных зависимостей сборки или готовой библиотеки игры в редакторе.

Автономный HTML использует `importmap` с модулями в data-URL; внутренние статические пути сопоставляются с точными копиями. В sandbox разрешён `data:` для скриптов, но запреты сетевых соединений при выключенной сети, `allow-scripts` без `allow-same-origin`, запреты workers и доступа к редактору сохраняются. Экспорт соседних модульных файлов использует относительные пути и требует HTTP. Его ограничение показано до сохранения.

Помеченная карта хранит контрольную сумму, исходный importmap и сведения о копиях; полная лицензия включена в HTML и каждый исполняемый модуль. Вынос проверяет метаданные, лицензии и замкнутость графа. Извлечённые модули получают ключ по SHA-256 содержимого и лицензии, не заменяют каталог версий и сохраняют привязку после правки приложения. Непомеченный или изменённый код остаётся как есть. Подготовка и экспорт не меняют исходник редактора; явное преобразование использует существующую историю.

## Профили игр и подключения

`src/ai-profiles.js` хранит ограниченный каталог точных подключений и необязательных требований. Рекомендация детерминирована; ручной выбор сохраняется, противоречия показываются без изменения кода. Жанр и стиль независимы. Параметры входят в снимок подготовки запроса, настройки и запись истории с версией схемы; изменение формы не меняет ранее скопированный текст. При изменении игры профиль создания не навязывается текущему исходнику. Старые записи без профиля продолжают работать.

Наблюдения о библиотеках получаются инертным текстовым сканированием. Метки встроенных копий и известные URL служат подсказками о версии, а не проверкой подлинности содержимого; произвольный JavaScript не анализируется. При приёме ответа пользователь выбирает запись для сопоставления. Внешние медиа, CSS и шрифты показываются существующим анализатором ресурсов. Сетевых обращений и выполнения кода при подготовке запроса или просмотре ответа нет.

Каталог классических библиотек дополнительно поддерживает ровно Phaser 4.2.1 через cdnjs/jsDelivr и распознаваемые локальные имена. Другие версии четвёртой ветки не выбираются автоматически. Применяются прежние ограничения размера, MIT-лицензия, кэш и проверка обратного преобразования. Phaser и Matter.js установлены как точные зависимости разработки для тестов; в HTML редактора они не включаются.

`tests/ai-profiles-unit.mjs` входит в unit и проверку чистой копии. `tests/ai-profiles.mjs` входит в `test:ai`: настройки, история, расхождения, темы и размеры экрана, затем настоящие фиксированные сборки Phaser 3/4, Matter.js и Three.js. Проверяются получение кода и полной лицензии из тестовых ответов CDN, чтение кэша, встраивание, сокращение, файлы рядом, сохранность исходника, изображение как текстура и звук в самостоятельном HTML при запрете сети. При недоступном WAV-декодере проверяются исходные байты, обработка отказа и независимая контрольная запись; это не считается подтверждением звучания. Доступ к реальным CDN и внешним ИИ при тестах не нужен. Качество ответов ботов и управление на физических устройствах проверяются отдельно.

## Локальные медиа

`src/media-assets.js` обслуживает изображения PNG/JPEG/WebP и звук MP3/OGG/WAV, выбранные пользователем. Тип проверяется по расширению и сигнатуре, копия адресуется SHA-256 содержимого. В IndexedDB `onehtml-lab-media/assets` сохраняются бинарные ArrayBuffer и проверенные имя/тип; представления Blob и data URL создаются в сеансе. При чтении кэша повторно проверяются сигнатура, размер и хеш; сохранённым производным URL доверия нет. Неподдерживаемое хранилище или квота оставляют копию в памяти с явным состоянием, не останавливая основной редактор. Удаление сначала завершает транзакцию и только потом убирает копию из памяти.

HTML хранит единственную версионную метку `onehtml-media:1` со списком точных относительных путей и идентификаторов. Это связывает текущий код и историю с собственными ресурсами без полного копирования бинарных данных в каждую запись. Текстовый сканер пропускает комментарии, JavaScript, сырой текст и неактивные template/noscript; изменение выполняется по диапазонам src и CSS url, без DOM-вставки пользовательской разметки. Повреждённые/дублированные метки, неверные форматы, внешние URL и больше 1 000 подключений не преобразуются. Поддержка не распространяется на srcset, SVG, видео, модели и динамические адреса.

Бюджеты: 8 МиБ на файл, 16 МиБ уникальных медиа документа, 32 МиБ/64 записи кэша, 32 миллиона кодовых единиц для сканирования. `prepareApplicationHtml/Files` сначала готовят библиотеки по исходному документу, сохраняя область локальных JS, затем подставляют медиа. Экспорт без обоих преобразований точный. При неполном наборе данных оставляются исходные подключения и метка; сообщения не обещают автономность. Предпросмотры миниатюр используют Blob URL и освобождаются при смене вкладки/закрытии экрана; звук не стартует автоматически. Новых зависимостей и сторонних лицензий в сборке нет.

```cmd
npm run test:assets
```

`tests/media-assets-unit.mjs` входит в штатные unit и проверки чистой копии. Браузерный набор проверяет Chromium/WebKit, file/HTTP, ширины 320/1365, оба редактора и темы: позиции вставки, точные привязки, изображение/CSS/звук, историю с разными копиями по одинаковому пути, кэш после перезагрузки, удаление и повторный выбор, квоту/отмену транзакции, повреждённые данные, сохранность исходника, размеры, сочетание с локальными библиотеками, точный и автономный экспорт. WAV реально воспроизводится при наличии поддержки кодека; при её отсутствии проверяется пояснение и сохранность данных, а не успешное звучание. CI и выпуск запускают `npm run test:assets -- --engines=chromium` без CDN. Проверка физических устройств и реального звучания остаётся ручной.

## Медиа в запросах ИИ

`src/media-prompts.js` связывает экспертный экран «Медиа», общий бинарный кэш и подготовку запросов. В список запроса входят выбранные оригинальные имена и используемые текущим кодом привязки. Файлы не отправляются боту автоматически. Одно имя выбирает одну копию; имена разных копий совпадающих файлов разрешаются явным выбором, а вложенные пути не сопоставляются по basename. Кодирование URL позволяет сохранить исходное имя с пробелами или нелатинскими символами.

Выбор и снимок последнего скопированного запроса хранятся в отдельной компактной записи localStorage, без бинарных данных. Автоматическая привязка выполняется только на вставке/импорте нового кода. Существующая версионная метка имеет приоритет; возврат истории и открытие примеров не перепривязываются. Изменение выбора после копирования не изменяет смысл уже отправленного запроса. Данные по прежнему идентификатору при удалении не подменяются другой копией.

Подготовка копии для ИИ убирает служебную метку и заменяет разрешённые привязки короткими именами. При флажке сокращения проверяет MIME, сигнатуру, размер и SHA-256 data URL, сохраняет их бинарную копию, затем использует короткие ссылки. CSS/HTML заменяются по диапазонам; JavaScript, комментарии и template не переписываются. Исходный код и история не меняются; кэш может получить извлечённые файлы. Выбор конкретных файлов и собственные изображения не входят в HTML поставки.

`tests/media-prompts-unit.mjs` входит в unit и проверку чистой копии; `tests/media-prompts.mjs` выполняется внутри test:assets. Проверяются исходные/Unicode-имена, отсутствие подкаталогов, точные байты скопированного запроса после смены выбора, оба редактора, file/HTTP и телефон/компьютер, повторное открытие, возврат истории, автономный экспорт и сокращение data URL без изменения исходника.

Основная задача всегда стоит первой; список медиа и правила ссылок дописываются в конец подготовленного запроса. Кнопка вставки изображения использует Clipboard.read в момент действия пользователя; запасной путь — ClipboardEvent.files только на экране «Медиа». Числовое имя назначается после проверки PNG/JPEG/WebP по сигнатуре и MIME, из общего набора номеров независимо от расширения, с учётом выбранных, сохранённых и отправленных имён. Повторные байты используют прежнюю копию. Исходный HTML и его вставка текста не меняются. Тесты медиа охватывают успешное чтение, запрет/отсутствие API, обычную вставку картинки, ошибочный формат и автоматические имена.
