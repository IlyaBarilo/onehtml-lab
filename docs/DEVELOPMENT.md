# Исходники и сборка

Готовое приложение — корневой `onehtml-lab.html`: самостоятельный HTML-файл без зависимостей во время работы. Этот файл создаётся из исходников и не включается в коммиты. Actions собирает его перед тестами и при публикации выпуска; готовый файл прикрепляется к выпуску. Для GitHub Pages из той же сборки создаётся копия с именем `index.html`. Коммиты в `main` запускают проверки, но не обновляют Pages; страница обновляется при публикации выпуска.

Для пересборки и проверок нужен Node.js 20 или новее. Из корня проекта выполните:

```cmd
node build.mjs
```

`src/template.html` задаёт разметку и политику безопасности, `src/styles.css` — оформление, `src/icons/` — SVG-значки, а `src/examples/` — игры-примеры. `src/app.js` управляет интерфейсом, `src/draft.js` хранит черновик и историю в IndexedDB, `src/compare.js` строит различия, `src/exporter.js` сохраняет и отправляет файл, `src/library-bundle.js` распознаёт точные версии классических библиотек по адресам CDN и локальным путям, загружает их вместе с MIT-лицензией по явному действию пользователя и хранит в отдельной базе IndexedDB, а `src/sandbox.js` создаёт изолированный предпросмотр и сообщает об ошибках игры. Локальный JS с лицензией также можно выбрать вручную; такая копия привязывается к SHA-256 исходного HTML и пути подключения, чтобы одинаковые имена файлов в разных играх не выбирали чужой код. При недоступном Web Crypto выбор действует только в сеансе. Все поддерживаемые библиотеки, включая Three.js r128, доступны для загрузки; готовых копий библиотек игр в сборке редактора нет. Подготовленное встраивается в сохранённую игру с выбранным флажком «Встроить библиотеки в файл». Для запуска самого редактора внешние шрифты, библиотеки и сервер не используются.

Экспорт с библиотеками поддерживает один HTML со встроенным кодом или отдельное скачивание HTML и JS-файлов. `src/exporter.js` подготавливает относительные ссылки и передаёт каждый файл браузеру через Blob без сетевых запросов. Имена версий и разрешение совпадений позволяют хранить все файлы в одном каталоге, MIT-лицензии включаются в JS. После передачи файлов окно сохранения показывает кнопки для скачивания каждого по отдельности, если браузер ограничил множественное скачивание. Проверки подготовки файлов входят в `test:unit`; браузерные проверки `test:libraries` скачивают HTML и JS, проверяют повторное скачивание при блокировке и запускают комплект из локального каталога.

`src/library-extract.js` выполняет обратное преобразование встроенных копий OneHTML Lab в CDN-ссылки той же версии или относительные подключения. Новое встраивание записывает исходный адрес, имя, доступный CDN-адрес и SHA-256 кода, а лицензия находится в отдельном помеченном комментарии. Вынос проверяет эти сведения без выполнения JS, переносит код вместе с лицензией в кэш с ключом по SHA-256 их содержимого и сохраняет полный HTML в истории. Старые помеченные копии требуют точного совпадения с кэшем; непомеченные или изменённые блоки не удаляются. Для контрольных сумм LF и CRLF приводятся к одному виду. Маленькие подключения сохраняют метку кэшированной копии, поэтому последующие правки игры не теряют её и не подменяют глобальный каталог версий. Окно сохранения выбирает подходящий вариант по этим подключениям. Логика входит в `test:unit` и чистую проверку; `test:libraries` дополнительно проверяет интерфейс, историю, кэш после перезагрузки и запуск отдельных файлов в Chromium и WebKit.

`src/workspace.js` управляет экранами рабочей области, возвратом к позиции кода, разворотом игры и общей строкой сообщений. Вспомогательные экраны сохраняют существующий iframe; открытие и закрытие меню не создаёт игру заново. Проверка `npm run test:workspace` охватывает переходы, выделение и прокрутку, сохранение при уменьшенной высоте, сообщения и разворот на мобильных и настольных размерах в Chromium и WebKit.

`src/editor.js` добавляет поиск, замену, навигацию и настройки нативного текстового поля. Отмена хранит текстовые изменения, до 100 действий с бюджетом 8 миллионов кодовых единиц; последнее действие сохраняется даже при превышении бюджета. Настройки вида находятся в отдельном ключе localStorage. Номера строк рисуются только для видимой области, геометрия переносов измеряется без исполнения HTML. В невидимой измерительной копии строки разделены на блоки, чтобы браузер не рассчитывал большой документ как один абзац с переносами. Переход к ошибке учитывает служебный префикс предпросмотра и доступен только при точном соответствии исходнику. Проверка `npm run test:editor` охватывает Chromium и WebKit, мобильные и настольные размеры, отмену, буквальные замены, сохранение настроек и документ размером более 2 МБ.

Поиск размещён над нативным полем кода, а кнопки точечной правки — под ним; их измеренная высота вычитается из области текста, включая режим разделённого экрана. Подсветка найденного фрагмента строится по безопасной измерительной копии и не меняет исходник. Отступы и парные символы используют общую цепочку отмены. `tests/editor-touch.mjs` входит в `test:editor` и проверяет сенсорные действия, границы выделения, копирование с отказом буфера, режим только чтения, подсветку без фокуса в коде и уменьшенную высоту окна. Уменьшение окна моделирует доступное место; физическая экранная клавиатура браузерным тестом не проверяется.

`src/ai-prompts.js` готовит запросы для создания, изменения и исправления игры, показывает текст и число символов перед копированием. Сокращение вызывает только читающую часть `planLibraryExtraction`: проверяет библиотеку и MIT-лицензию, заменяет её точной CDN-ссылкой в копии, не меняет редактор, историю или кэш и не делает сетевых запросов. Результат асинхронной проверки применяется только к актуальным параметрам запроса. Проверка `npm run test:ai` охватывает Chromium и WebKit, локальный файл и HTTP, размеры экрана, сообщения об ошибках, отказ буфера, сохранность исходника и библиотек, а также смену задачи во время проверки.

`src/desktop.js` управляет расположением кода и игры рядом на экранах от 1000 пикселей, разделителем и размером предпросмотра. Настройки хранятся в отдельном ключе localStorage. Изменение расположения и масштаба сохраняет тот же iframe; ручной перезапуск создаёт новый. Размер телефона задаётся до подключения iframe к документу. Ошибки привязаны к запущенному исходнику, чтобы правки редактора не приводили к переходу на неверную строку или подготовке запроса по другой версии. Проверка `npm run test:desktop` охватывает Chromium и WebKit: изменение размеров, сохранность игры, редактирование, перезапуск, экспорт и настройки. Вариант `node tests/desktop.mjs --http` дополнительно проверяет HTTP через временный локальный сервер.

`src/diagnostics.js` расширяет экран сообщений списком последних 50 различных событий запуска и управлением библиотеками. Повторы объединяются; исходник и доступные позиции ошибки привязаны к конкретному запуску. Проба в изолированном iframe сообщает об ошибках, отклонениях Promise, `console.warn`, `console.error` и ошибках ресурсов, сохраняя штатный вызов консоли. Поток ограничен 100 сообщениями в секунду с отдельным предупреждением; интерфейс обновляет список не чаще десяти раз в секунду при поступлении сообщений. Отчёт не включает HTML; подготовка ИИ-запроса может добавить его через существующий механизм.

Список библиотек разбирает текущий текст без исполнения и сетевых запросов, использует существующие правила распознавания и загрузки с MIT-лицензиями. Постоянные и временные копии различаются по фактически сохранённой записи. Удаление выполняется одной транзакцией только в базе библиотек; память меняется после успешного завершения. При отказе транзакции список сохраняется. Проверка `npm run test:diagnostics` охватывает Chromium и WebKit, узкий и широкий экран, ошибки и повторы, безопасный вывод текста, отчёт и связь с исходником, встроенные и внешние подключения, локальные файлы, отказ удаления, перезагрузку и недоступную IndexedDB. Вариант `node tests/diagnostics.mjs --http` дополнительно проверяет HTTP.

`src/readiness.js` добавляет разделы ресурсов и скорости. Статический текстовый разбор HTML и встроенных стилей не подключает пользовательский DOM и не выполняет запросов. В списке запуска объединяются Resource Timing, ошибки ресурсов и события CSP; принимаются только сообщения действующего iframe, число адресов ограничено 200. Измерение интервалов `requestAnimationFrame` выключено по умолчанию, при включении сообщает результат раз в секунду и исключает фоновые и вспомогательные экраны. Пробы добавляются только в предпросмотр, экспорт игры их не содержит. Проверка `npm run test:readiness` охватывает Chromium и WebKit, мобильный и настольный размеры, статические и динамические ресурсы, блокировку сети, подстановку библиотеки, FPS, отчёт, смену исходника и сохранение настройки. Вариант `node tests/readiness.mjs --http` добавляет HTTP; разбор ресурсов и часы измерения также проверяются в `test:unit`.

Проверка `npm run test:workshop` проходит сценарий занятия в Chromium и WebKit: памятку, готовую игру без сети, замену текста, ошибочный и исправленный ответы ИИ, сравнение, возврат версии, скачивание и запуск отдельного HTML. Ответы ИИ и доступ к буферу подставляются тестом; реальные сервисы и системное меню вставки не вызываются. Сетевые запросы блокируются; для Chromium дополнительно включён режим offline, а WebKit проверяется блокировкой запросов из-за ограничения навигации по локальным файлам в его режиме offline. Проверки выполняются на узком и широком экране, без физических телефонов.

`src/syntax.js` содержит собственный ограниченный разбор HTML/CSS/JavaScript для оформления. Цветной слой строится только для видимых строк через текстовые узлы; нативное поле сохраняет ввод, выделение и прокрутку. Подключения получают пояснения, CSS-цвета — образцы с контрастными буквами и шахматной подложкой для прозрачности. Цвет букв выбирается по контрасту с обеими клетками после наложения альфа-канала. Оформление образца не меняет размеры символов. Это подсветка, а не полный анализатор языка или проверка ошибок. При вводе через IME временно виден обычный текст. Файлы больше миллиона кодовых единиц UTF-16, строки длиннее 12 тысяч и результаты больше 60 тысяч токенов показываются без подсветки. Разбор входит в `test:unit`; `test:syntax` проверяет Chromium и WebKit, геометрию текста, настройки, ввод, поиск, отсутствие исполнения исходника и точное сохранение HTML.

`src/comparison-game.js` запускает текущий исходник и выбранную запись истории в отдельном sandbox iframe. Одновременно существует только один iframe сравнения; смена версии, вкладка кода и закрытие удаляют его. Сеанс содержит два ограниченных временных хранилища, не зарегистрированных в постоянном хранилище игры. Сообщения принимаются только от действующего iframe, асинхронная подготовка отменяется счётчиком запуска. Загрузка и выбор библиотек используют общий механизм с привязкой к сеансу и версии вместо текста редактора. `test:comparison-game` проверяет выбор записи, изоляцию, временные данные, ошибки, сеть, CDN и локальные библиотеки, неизменность экспорта и отмену запуска в Chromium/WebKit на узком и широком экранах.

`src/alternative-editor.js` подключает CodeMirror 6 к общему исходнику и цепочке отмены обычного редактора. CodeMirror используется по умолчанию; разбор HTML со встроенными CSS/JavaScript поддерживает ручное сворачивание и общие смысловые акценты. Видимые блоки не определяют экспорт: все действия используют полный текст. Переключатели редактора и темы закреплены справа в нижней панели в обоих режимах. Выбор хранится в отдельных ключах localStorage; сворачивание действует в сеансе. Тёмная тема задаёт отдельные цвета подсветки и не меняет документ игры. `test:alternative-editor` проверяет Chromium и WebKit на узком и широком экранах: начальные настройки, переключение без потери кода и курсора, закреплённые кнопки, обе темы и их сохранение, сворачивание, копирование скрытого текста, поиск, отмену, вставку и историю, импорт, экспорт, режим только чтения, предпросмотр и работу без сети. Остальные сценарии явно выбирают обычный редактор через `tests/native-editor.mjs`, сохраняя проверку его собственного ввода и геометрии.

Готовая копия CodeMirror находится в `src/vendor/codemirror.bundle.js` и включается обычной сборкой без npm, сети и каталога `local/`. Для её обновления после установки зависимостей выполните `npm run build:editor`, затем `npm run build`. `scripts/build-codemirror.mjs` собирает `src/codemirror-entry.js` через esbuild и автоматически сохраняет полные MIT-лицензии всех вошедших пакетов в JS, `src/vendor/codemirror-LICENSE.txt` и список версий в [THIRD_PARTY.md](THIRD_PARTY.md). Неизвестная лицензия останавливает пересборку. Эти три результата нужно обновлять вместе. Встроенный редактор увеличивает HTML примерно на 500 КБ; проверка сборки ограничивает размер редактора со всеми примерами и заданиями 1,15 МБ.

Каталог использует метаданные примеров в `build.mjs`, самостоятельные HTML в `src/examples/` и задания в `src/example-lessons.js`. Задания не добавляются в экспортированный исходник. Запрос для задания берёт текущий код, а связь с открытой копией использует существующую область хранения примера. Для мультимедийного проекта запрос изменения относится к приложению; создание новой игры сохраняет свой прежний сценарий.

```cmd
npm run test:learning
```

Проверка учебного пакета охватывает Chromium и WebKit, локальный файл и HTTP, оба редактора и темы, задания четырёх примеров, ручную правку, запросы с актуальным кодом, буфер и ручное копирование, действия в примерах, историю и возврат, точный экспорт и запуск скачанной копии без внешних ресурсов, восстановление черновика. Вариант `npm run test:learning -- --engines=chromium` используется в проверках коммитов и выпусков. Снимки и скачанные примеры сохраняются во временном каталоге системы.

Тест браузера по умолчанию открывает локальный `onehtml-lab.html`. Команда `node tests/browser.mjs --http` дополнительно проверяет страницу через временный HTTP-сервер; он не нужен для использования приложения. Результаты сохраняются во временный каталог системы или по пути `TEST_RESULTS_DIR`.

Разбор шести учебных примеров описан отдельно в `src/code-guide.js`. Он использует уже включённый HTML/CSS/JavaScript-парсер CodeMirror, не выполняет пользовательский код и не требует новых зависимостей. Уникальные структурные участки ищутся в актуальном исходнике; отсутствующие, неоднозначные или синтаксически повреждённые узлы недоступны. Результат кэшируется по исходнику и примеру; документы больше 500 000 единиц UTF-16 не разбираются. Карта определяется областью открытой копии примера, сохраняющейся с черновиком. Обычный импорт получает другую область; история хранит текст, а не карту исходного примера.

```cmd
npm run test:guide
```

Набор проверяет Chromium и WebKit через file/HTTP, телефонные и компьютерные размеры, оба редактора и темы: структурные переходы после правок, удаление и неоднозначность узлов, раскрытие свёрнутого блока, актуальное выделение и контекст объяснения, выбранную историю и отказ от сравнения, сокращение библиотек обеих версий, сохранность исходника/истории и точный экспорт. В CI используется `npm run test:guide -- --engines=chromium`. Режимы объяснения и проверки не требуют ответа в виде нового HTML; выбранная для анализа запись истории действует в текущем сеансе, при её удалении используется последняя оставшаяся версия.

Звуковая панель (`src/examples/sound-panel.html`) использует Web Audio с созданием/возобновлением контекста после действия, ограничением числа осцилляторов и остановкой в фоне. Витрина (`src/examples/3d-showcase.html`) использует классическую сборку Three.js r160 через существующий механизм получения и экспорта. Она не требует моделей/текстур, рисует по изменению состояния, ограничивает плотность пикселей и запускает цикл кадров только при автоповороте. Библиотека `three` версии `0.160.0` — зависимость только тестов; в сборку редактора её исходник не входит. Лимит самостоятельного HTML — 1 200 000 байт, включая оба редактора и пять мультимедийных примеров.

```cmd
npm run test:media
```

Проверки проходят через file/HTTP с обоими редакторами, темами и размерами 320, 390, 1365. Они используют реальные узлы Web Audio и npm-копию Three.js вместо CDN: пользовательский старт, разные осцилляторы, громкость/выключение, фон, материалы/свет/камера/вращение, уменьшение движения, задания, карты, экспорт с полной MIT-лицензией, кэш без сети и возврат истории. В Chromium WebGL проверяется с программным рендерером; при недоступности WebGL в WebKit проверяется явное пояснение, а не успешная отрисовка. Отдельно проверяются отсутствие аудио, WebGL и библиотеки. Автоматика не оценивает звучание на реальных динамиках; это часть ручной проверки. CI запускает `npm run test:media -- --engines=chromium` без обращения к внешним ресурсам.

Публикационная сборка получает номер из тега выпуска: `node build.mjs --release-tag=v1.0.0`. Обычная локальная сборка не показывает номер версии. Автоматические проверки и выпуск описаны в файлах `.github/workflows/`.

Локально подготовить тот же пакет для Pages можно командой `node scripts/prepare-pages.mjs` после сборки. Файл появится в `dist/pages/index.html` и должен побайтно совпадать с корневым `onehtml-lab.html`; проверить это можно командой `npm run test:pages`. Каталог `dist/` не входит в коммит.

Изображения интерфейса в `assets/` можно обновить командой `node scripts/capture-assets.mjs` после пересборки. Она делает снимки настоящего приложения; для неё нужен установленный Playwright Chromium.
